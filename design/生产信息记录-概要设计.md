# 生产信息记录 概要设计

对应 PRD：`../prd/生产信息记录-PRD.md`

## 1. 架构位置

沿用现有分层（Controller → Service → MyBatis-Plus Mapper），新增 `production_record` 表。导出使用 Apache POI（poi-ooxml 5.2.5，JDK8 兼容）在服务端生成 xlsx。

## 2. 数据库

```sql
CREATE TABLE IF NOT EXISTS `production_record` (
  `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
  `serial_no`   VARCHAR(24)  NOT NULL COMMENT '流水号 PR+yyyyMMdd+4位',
  `operator`    VARCHAR(32)  DEFAULT NULL COMMENT '作业员',
  `rack_no`     VARCHAR(32)  NOT NULL COMMENT '吊架号',
  `feed_slot`   VARCHAR(32)  DEFAULT NULL COMMENT '投料槽位名称',
  `feed_time`   DATETIME     NOT NULL COMMENT '投料时间',
  `in_time`     DATETIME     DEFAULT NULL COMMENT '进线时间',
  `out_time`    DATETIME     DEFAULT NULL COMMENT '出线时间，空=正在加工',
  `batch_no_l`  VARCHAR(64)  DEFAULT NULL COMMENT '批号(左)',
  `item_no_l`   VARCHAR(64)  DEFAULT NULL COMMENT '料号(左)',
  `spec_l`      VARCHAR(32)  DEFAULT NULL COMMENT '规格(左)',
  `resistance_l` VARCHAR(32) DEFAULT NULL COMMENT '阻值(左)',
  `tolerance_l` VARCHAR(32)  DEFAULT NULL COMMENT '精度(左)',
  `qty_l`       INT          DEFAULT NULL COMMENT '数量(左)',
  `batch_no_r`  VARCHAR(64)  DEFAULT NULL COMMENT '批号(右)',
  `item_no_r`   VARCHAR(64)  DEFAULT NULL COMMENT '料号(右)',
  `spec_r`      VARCHAR(32)  DEFAULT NULL COMMENT '规格(右)',
  `resistance_r` VARCHAR(32) DEFAULT NULL COMMENT '阻值(右)',
  `tolerance_r` VARCHAR(32)  DEFAULT NULL COMMENT '精度(右)',
  `qty_r`       INT          DEFAULT NULL COMMENT '数量(右)',
  `created_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_serial_no` (`serial_no`),
  KEY `idx_feed_time` (`feed_time`),
  KEY `idx_rack_no` (`rack_no`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='生产信息记录';
```

状态不落库（R3 由 out_time 是否为 NULL 计算）。

## 3. 接口契约

统一前缀 `/api/prod-records`，响应包与现有模块一致。

### K1 分页查询

`GET /api/prod-records?feedTimeStart&feedTimeEnd&batchNo&rackNo&page=1&size=20`

- feedTimeStart/feedTimeEnd：`yyyy-MM-dd HH:mm:ss`，可空，闭区间按 feed_time 过滤。
- batchNo：包含匹配 `batch_no_l LIKE %x% OR batch_no_r LIKE %x%`。
- rackNo：精确等值。
- 排序 feed_time DESC, id DESC。page/size 校验同 I1。
- 响应：`{ total, records: [ProdRecordVO] }`，VO 含上述全部字段 + `status`（PROCESSING/DONE，服务端计算）。

### K2 导出 Excel

`GET /api/prod-records/export?（参数同 K1，不含分页）`

- 查询条件与排序同 K1，**不分页**，导出全部命中行。
- 响应 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`；`Content-Disposition: filename*=UTF-8''生产记录_yyyyMMddHHmmss.xlsx`。
- 列头 20 列与列表一致；时间列 `yyyy-MM-dd HH:mm:ss`；状态列中文（正在加工/已完成）；空值输出空串。

### K3 新增记录（扫码上料「发送」预留）

`POST /api/prod-records`，body：

```json
{
  "operator": "张三", "rackNo": "HJ-01", "feedSlot": "上下料",
  "inTime": null, "outTime": null,
  "batchNoL": "B1", "itemNoL": "P1", "specL": "0603", "resistanceL": "10Ω", "toleranceL": "±1%", "qtyL": 3000,
  "batchNoR": "B2", "itemNoR": "P2", "specR": "0603", "resistanceR": "100Ω", "toleranceR": "±5%", "qtyR": 2500
}
```

- rackNo 必填；流水号服务端生成（PR+日期+4位流水，重试 3 次）；feedTime=服务端当前时间；成功 201 返回 VO。
- 本期无页面入口，供扫码上料模块调用与联调造数。

## 4. 服务层要点

- `ProdRecordService.page(query)` / `export(query)` 复用同一 `buildWrapper` 与排序，保证 R4 所见即所得。
- 导出：POI `XSSFWorkbook`，首行表头加粗，列宽按内容估算；行数上限 10 万行防御。
- 流水号生成与配方 REC 同思路：查当日最大流水号 +1，冲突重试 3 次。

## 5. 前端

`ProdRecordList.vue`：

- 筛选区：datetimerange（投料时间区间）、批号 input、吊架号 input、查询/重置；导出按钮（当前条件）。
- 表格 20 列固定列序，横向滚动；状态列 el-tag（PROCESSING→warning「正在加工」/ DONE→success「已完成」）；空出线时间显示 '—'。
- 分页默认 20，sizes [10,20,50,100]。
- 导出：`fetch('/api/prod-records/export?…')` blob 下载，文件名取响应头 Content-Disposition。

路由 `/prod-records`，左侧菜单独立大模块"生产信息记录"。

## 6. 部署与依赖变化

- pom 新增 `org.apache.poi:poi-ooxml:5.2.5`（连带 xmlbeans/commons 集合等，mvn 自动拉取）。
